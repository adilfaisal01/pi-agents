MODELS: bundled catalog + ~/.pi/agent/models.json overlay; CUSTOM providers (ollama, ollama-cloud) enumerate models BY HAND, so `pi update --models` never adds a newly served id — "cannot find model X" almost always means it is missing from that list (diagnose: bearer GET ollama.com/v1/models with $OLLAMA_API_OPENCODE_KEY; `--list-models` fuzzy-matches so a miss returns lookalikes). ~/.local/bin/ollama-cloud-sync [sync|check|status] (repo /mnt/E/github-projects/ollama-cloud-sync, UNCOMMITTED; systemd user timer daily+Persistent; key ~/.config/ollama-cloud-sync/env 0600) keeps providers["ollama-cloud"] equal to what ollama.com serves (ids + /api/show capabilities and context_length → contextWindow/reasoning/input; vanished ids pruned after 3 syncs; check exits 1 drift / 2 config / 3 API); only ollama-cloud is owned, local `ollama` stays hand-curated. SUBAGENTS (v-model-agents): NO per-call model param — model only from frontmatter `model: <provider>/<id>`, pushed to the child as --model; omitting it inherits the dispatcher model AND thinking level, setting it drops the level. Frontmatter: name/description/tools/model (+ local write_scope). Roots: package pi/agents/ < ~/.pi/agent/agents/*.md (scope "user", default) < nearest .pi/agents (needs scope project/both); discovery uncached. code-review-swarm = review-correctness (mimo-v2.6-flash) + review-quality (mistral-large-4) in parallel, read-only, one SEV1-SEV4 table.
MCP: the ADAPTER owns config so lifecycle/timeouts are honoured (built-in Pi reads only mcpServers/autoEnableCodemode from mcp.json). ~/.pi/agent/mcp-adapter.json holds anydoc, github, local_vision, railway (lazy; `railway setup agent -y` rewrites mcp.json so keep it here), books, vault + settings{toolPrefix:"server"}; both mcp.json = {"mcpServers":{}} ⇒ no mcp__* tools, everything via mcp({server|search|describe|tool}) with single-underscore names (e.g. books_search_books). PROJECT .mcp.json IS DOUBLE-GATED: trust.json (findNearestTrustEntry walks UP) + mcp-project-approvals.json keyed by realpath(cwd) and definitionHash=sha256(canonical definition) — a repo move silently revokes approval ("⊘ blocked: project server approval denied"); re-approve via hashProjectServerDefinition (~/.pi/agent/npm/node_modules/pi-mcp-adapter/dist/project-server-trust.js), then /reload. CORPUS (lazy, skill global:reference-local-corpus): books = /mnt/E/sabrina-sandbox/book-knowledge-mcp (venv ~/.hermes/mcp/venv, DBs ~/.hermes/book_dbs); vault = ~/.hermes/mcp/vault-mcp/server.py (vault_*, context/lecture/analytical search, recall); hybrid BM25+cosine via qwen3-embedding:0.6b on Ollama :11434 (dead Ollama → keyword-only + warning).
MEMORY TOOLING: hermes-memory-config.json autoConsolidate:true + overflowStrategy "auto-consolidate" + overflowGraceMs 0; restart pi after config changes; 20000-char store. memory_remove must NEVER be batched (concurrent removes once wiped the store) and deletes the FIRST entry matching the text; memory_replace won't drop sentences → compressing = remove + add.
TUI PROBES: /btw (pi-btw-extension) works ONLY in a real TUI — lib/ui.ts openOverlay hard-guards ctx.mode !== "tui", so `pi -p "/btw q"` exits 0 silently; prove it over a python pty.fork (tmux is NOT installed) with `pi --tui-mode regular -ne -e <ext>/index.ts --no-session --model ollama-cloud/deepseek-v4.1-flash`, attempt landing in ~/.pi/agent/btw/threads-<sha256(cwd)[:12]>.json. Never judge a TUI from ANSI-stripped output (stale spinner frames look like a hang). Extension HTTP servers bind 127.0.0.1 with token/CSRF (curatorRemote:true → 0.0.0.0).
